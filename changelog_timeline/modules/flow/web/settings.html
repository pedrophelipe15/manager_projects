Remove issues Done resolvidas há mais de 6 meses. Recomendado executar semanalmente.

Como o expurgo funciona?

Critério (qual data é usada): uma issue é expurgada quando atende às três condições:

  • está com status Done (apenas "Done" — Resolved, Canceled e Reject não são expurgados);
  • possui data de resolução (resolved_at, vinda do resolutiondate do Jira) preenchida;
  • essa resolved_at é anterior a 26 semanas (~6 meses) atrás;
  • e não tem pai vivo: a issue só é expurgada se não tiver parent OU se o parent também for elegível (Done + 6 meses). Assim, uma subtask nunca é apagada enquanto a história-pai permanecer no banco — preserva a árvore e evita perder métricas.

Somente o resolved_at entra no critério de data. Created, Updated e Due Date são ignorados — uma issue atualizada recentemente, mas resolvida (Done) há mais de 6 meses, é candidata.

Os dados são apagados ou só marcados? São apagados fisicamente da base (DELETE), não marcados nem arquivados. Para cada issue expurgada, são removidos: a própria issue, seus eventos de changelog e seus registros de métricas. A ação é irreversível — os dados só voltam recoletando do Jira via "Atualizar".

Dica: use "Ver issues que serão removidas" para inspecionar e filtrar a lista exata antes de confirmar. O preview usa exatamente o mesmo critério do expurgo.
